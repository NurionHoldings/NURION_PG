# Synthetic NURION PG P0 Design Baseline RFC (#3101~#3500)

이 단계는 실제 PG를 작동시키는 구현이 아니라, 이후 구현이 따라야 할 P0 설계 기준선을 합성·메모리 전용 RFC로 고정한다. 정확히 16개 workstream에 각 25개 통제를 배치한다.

## 설계 영역

1. 도메인 용어집
2. 결제승인과 내부결재의 구분
3. 신뢰경계
4. 토큰화 데이터 흐름
5. 개념 자금 흐름
6. 복식원장 스키마와 불변식
7. 결제 상태기계
8. 취소·환불 상태기계
9. 정산·하위원장 상태기계
10. 대사 예외 모델
11. 멱등·동시성 계약
12. inbox/outbox·서명 webhook 계약
13. tenant 권한·maker-checker·break-glass
14. 불변 감사·재해복구·관찰성·SLO
15. 홈·포털·상세페이지 및 관련 레코드 그래프
16. 공식 근거 추적성·최신성·운영자 승인 게이트

## 안전 경계

- 구조화 근거는 URL, 문서명, 조회일, 분류, 만료일, content digest, 검토 여부를 결속한다.
- 만료·미검토·중복·변조된 근거는 fail-closed 처리한다.
- 공식 근거 URL은 승인된 법령·표준·공식 기술문서 도메인 allowlist를
  통과해야 하며 임의 HTTPS 주소는 근거로 등록할 수 없다.
- 각 요구사항은 workstream/control ID, 근거, 위협, 수용 증적, 책임 역할, 운영자 승인 필요 여부를 결속한다.
- RFC는 #3101~#3500 전체 400개 통제를 빠짐없이 포함해야 작성·기록할 수 있다.
- 검토 배치는 최대 20개이고 author/reviewer/verifier/auditor를 분리한다.
- 일반인 문구는 고정 allowlist만 사용하며 자유 prompt나 가중치를 변경하지 않는다.
- 실제 결제·승인·취소·환불·정산·송금·원장·외부 PG·UI 생성·배포 능력은 없다.

구조화 근거는 법률자문이나 운영 의무의 단정이 아니다. 실제 적용 전 담당 법무·보안·회계 검토와 운영자의 명시적 승인이 필요하다.
