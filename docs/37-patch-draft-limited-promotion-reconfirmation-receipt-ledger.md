# 기능 #037 — Patch Draft 제한승격 재확인 의사 수신대장

기능 #036에서 검증된 합성 재확인 의사를 재시작 가능한 SQLite 증거로 보존한다.
이 대장은 최인석 운영자의 실제 재확인이나 승인 결과를 기록하지 않고 제한승격·
활성화·rollback을 실행하지 않는다.

## 저장 계약

- 합성 평가·봉투·nonce·재확인 패킷·Shadow ID와 SHA-256
- 합성 운영자 ID와 선택값
- 검증 평가 원문 JSON과 timezone 포함 기록시각
- 이전 감사 다이제스트에 연결된 append-only 감사행

파일 DB는 `synthetic-` 접두어와 `.db`, `.sqlite`, `.sqlite3` 확장자만 허용한다.
서버 DB, URI와 운영 저장소는 거부한다.

## 실패 폐쇄

- 평가 사슬·다이제스트·합성 전용 메타데이터가 깨지면 기록하지 않는다.
- 평가보다 이른 시각과 timezone 없는 시각을 거부한다.
- 평가·봉투·nonce·패킷·Shadow 결합을 저장행마다 재검증한다.
- 같은 증거 재전송은 멱등 처리하고 한 패킷·Shadow의 복수 수신증을 차단한다.
- 저장행과 감사행을 단일 트랜잭션으로 기록하고 실패하면 rollback한다.
- 재시작 후에도 저장 결합과 감사 사슬을 검증한다.
- 저장행·감사행 위변조가 발견되면 이후 기록을 차단한다.

## 권한 경계

최대 상태는
`SYNTHETIC_PATCH_DRAFT_LIMITED_PROMOTION_RECONFIRMATION_RECEIPT_RECORDED`다.
이는 합성 검증 결과의 수신증일 뿐 실제 승인·보류·거절 또는 재확인 기록이 아니다.
코드·patch·diff 생성, 파일 변경, 제한승격·rollback 실행, 결제·송금,
병합·배포·운영 활성화 메서드는 없다.
